# すれちがいクエスト（仮）

DSのすれちがい通信のようなスマホゲームのMVPです。Bluetoothは使わず、**位置と時刻をサーバーで照合する「擬似すれちがい」**で動きます。すれちがった人が助っ人として届き、その力を借りて敵を倒していくRPGです。

- 最初に4つのジョブ（剣士・魔法使い・僧侶・踊り子）から1つ選ぶ
- 出かけた先でアプリを開くと、近く（約150m四方＋周囲8マス）で2時間以内にアプリを開いた人とすれちがう。相手は1〜3時間後に助っ人として届く
- すれちがった人数（累計）でレベルが上がる。必要人数は「(レベル−1)² ÷ 2」
- 歩数（2,000歩ごと）と移動距離（10kmごと、乗り物込み）でも旅人（NPCの助っ人）が加わる。1日5人まで
- 冒険には助っ人を3人まで連れて行ける。助っ人は1回力を貸したら帰っていく（使い切り）
- メッセージ・フレンド・ランキング・課金はなし

設計の背景は Claude の設計メモ「擬似すれちがい通信ゲーム 設計メモ」にまとめてあります。

## 構成

npm workspaces のモノレポです。

| ディレクトリ | 中身 |
| --- | --- |
| `packages/shared` | サーバーとアプリで共有するゲームロジック。ジョブ、レベル曲線、ジオハッシュ、旅人の計算、名前のチェック、バトルエンジン、エリアと敵 |
| `apps/server` | API（Cloudflare Workers + D1 + Hono）。すれちがいの照合、旅人の付与、冒険の検証、ブロック・通報、定期削除 |
| `apps/mobile` | スマホアプリ（Expo / React Native）。iOS・Android、開発用にWebでも動く |

### 仕組みのポイント

- **位置**: アプリが端末の中で緯度経度を7桁のジオハッシュ（約150m四方）に丸め、それだけを送る。サーバーは生の緯度経度を持たない。位置記録は48時間で消える
- **遅延配信**: すれちがいは1〜3時間後に届く。位置送信の返事にも「すれちがったか」は含めない。今どこに誰がいるかを特定させないため
- **相手の情報**: 届くのは表示名・アバター・ジョブ・レベルの写しだけ。相手のIDや位置はアプリに渡さない。ブロック・通報も助っ人カードのIDで行う
- **バトルの改ざん対策**: 冒険の開始時にサーバーがシードを決め、アプリは行動の列だけを送り返す。サーバーは同じバトルエンジン（`packages/shared`）で再生して勝敗を確かめる
- **冒険の再開**: 途中でアプリが閉じても、保存したシードと行動の列から同じ場面を再現して続きから遊べる

## ローカルで動かす

Node.js 22 以上が必要です。

```bash
npm install

# サーバー（http://localhost:8787）
cd apps/server
cp .dev.vars.example .dev.vars     # すれちがいがすぐ届く・送信間隔の制限なし（開発用）
npm run db:migrate:local
npm run dev
```

別のターミナルでアプリを起動します。

```bash
cd apps/mobile
cp .env.example .env               # 実機で試す時は EXPO_PUBLIC_API_URL をPCのLAN内IPに
npx expo start
```

使っているネイティブ機能（expo-location / expo-sensors / expo-secure-store）は Expo Go に入っているので、Expo Go でそのまま試せます。`w` キーでブラウザ版も開けます（歩数は取れません）。

近くに他のプレイヤーがいない状態で試すには、API で架空のプレイヤーを作って同じ場所で位置を送ると、すれちがいが起きます（`apps/server/scripts/e2e.ts` の `newPlayer` が参考になります）。

## テスト

```bash
npm test             # 共有ロジックのテスト＋サーバーの通しテスト
npm run balance      # エリアごと・ジョブごとの勝率表（バランス確認）
npm run typecheck    # 3つのパッケージの型チェック
```

- `packages/shared/test/balance.test.ts` はバランスの目標を確かめます。エリア1はレベル1・ひとりでもどのジョブでも勝てる、各エリアは推奨レベル・助っ人3人ならどのジョブでも勝てる、エリア2以降は助っ人なしだと勝てない、などです
- `apps/server/scripts/e2e.ts` はローカルの D1 で `wrangler dev` を立ち上げ、複数の架空プレイヤーで53項目を確かめます（すれちがいの遅延、1日の上限、移動距離・歩数の旅人、冒険の検証、ブロック、位置記録の削除、アカウント削除など）。時刻は `x-debug-now` ヘッダーで動かします（`DEBUG_TIME=1` の時だけ有効）

## 本番にデプロイする

### サーバー（Cloudflare）

```bash
cd apps/server
npx wrangler login
npx wrangler d1 create pieris          # 表示された database_id を wrangler.jsonc に書く
npm run db:migrate:remote
npm run deploy
```

本番では `.dev.vars` の値（`DEBUG_TIME` など）は設定しません。1時間ごとの定期処理（cron）で、48時間を過ぎた位置記録を消します。

### アプリ（EAS）

1. `apps/mobile/app.json` の `bundleIdentifier` / `package`（いまは `com.example.pieris`）、アプリ名、アイコンを差し替える
2. `EXPO_PUBLIC_API_URL` を本番のAPIのURLにする（EAS の環境変数に設定）
3. `npx eas-cli@latest build --platform all` でビルドし、`eas submit` で提出

## 調整できる値

ゲームの数値は `packages/shared/src` にまとまっています。変えたら `npm run balance` で勝率を確かめてください。

| 内容 | 場所 |
| --- | --- |
| 1日の上限（すれちがい10人・旅人5人）、歩数・距離の単位、時間窓、遅延、保存期間 | `constants.ts` |
| レベル曲線 | `level.ts` |
| ジョブの能力値、技の倍率、助っ人の強さ | `jobs.ts` |
| エリア・敵の編成と強さ | `areas.ts` |

## まだやっていないこと

- **Android の歩数**: MVPではアプリを開いている間の歩数だけを数えます。閉じている間の分も取るには Health Connect の連携（開発ビルドが必要）を足します。iOS は OS に残っている今日の歩数をまとめて読みます
- **バックグラウンドの位置（方式B）**: 今は「アプリを開いた時だけ」です。持ち歩くだけで成立させるなら、常時許可とストア審査の対応が要ります
- **端末の検証**: 位置偽装への対策は、送信間隔の制限・時速400km超の除外・1日の上限まで。本格運用では App Attest / Play Integrity を足します
- **登録の連打対策**: `/v1/register` に回数制限がありません。Cloudflare の Rate Limiting などで絞ってください
- **見た目**: 敵とジョブは絵文字で仮置きです。アイコンもテンプレートのままです
- **ストア提出の準備**: プライバシーポリシーのページ、位置情報の利用目的の説明（`app.json` に下書き済み）、通報の運用フロー
